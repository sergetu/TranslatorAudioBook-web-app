# TranslatorAudioBook-web-app

**TranslatorAudioBook-web-app** — self-hosted веб-приложение для перевода и озвучки китайских веб-романов.

Приложение объединяет полный цикл обработки книги:

```text
TXT → определение глав → перевод → проверка → TTS → чтение и прослушивание
```

Книга загружается через браузер, разбивается на главы по китайским заголовкам, переводится локальной моделью или через DeepSeek API и озвучивается через `edge-tts`.

Обработка выполняется по главам через очередь задач, поэтому отдельную главу можно перевести повторно, исправить вручную, переозвучить или перезапустить после ошибки без повторной обработки всей книги.

Приложение рассчитано прежде всего на небольшое self-hosted развёртывание в локальной сети, но включает пользовательскую авторизацию, изоляцию данных, repository-слой и другие элементы, позволяющие развивать его дальше как сетевой сервис.

---

## Возможности

### Пользователи и библиотека

- регистрация по email и паролю;
- первый зарегистрированный пользователь автоматически получает роль администратора;
- администратор может создавать пользователей и других администраторов;
- сброс паролей и отключение аккаунтов из административного интерфейса;
- открытая регистрация может быть отключена;
- обычный пользователь работает со своей библиотекой;
- администратор имеет доступ ко всем книгам и задачам.

---

### Книги и главы

- загрузка `.txt` непосредственно через браузер;
- автоматическое определение `UTF-8` и `GB18030`;
- настраиваемый лимит размера загружаемого файла;
- поддержка обложек;
- определение глав по китайским заголовкам:

```text
第N章
第N节
第N回
```

Разбиение выполняется по **исходному китайскому тексту до перевода**.

Для каждой главы отдельно отслеживаются:

- состояние перевода;
- состояние TTS;
- ошибка обработки;
- количество символов;
- количество аудиофрагментов.

Длинная глава при необходимости дополнительно разбивается на части внутри одной логической главы.

## Перевод

Поддерживаются два провайдера перевода через единый pipeline.

### Local / koboldcpp

Локальная модель через OpenAI-совместимый API `koboldcpp`.

Проверенная конфигурация:

```text
HY-MT1.5-7B-Q4_K_M
```

Поддерживаются:

```text
raw  → /v1/completions
chat → /v1/chat/completions
```

Через настройки задаются:

- URL koboldcpp;
- модель;
- размер контекста;
- формат запроса;
- системный prompt;
- параметры очереди.

По умолчанию используется:

```text
http://127.0.0.1:5003
context: 8192
```

### DeepSeek

Второй провайдер использует DeepSeek API.

Настраиваются:

- API endpoint;
- модель;
- системный prompt;
- максимальная параллельность запросов.

По умолчанию:

```text
https://api.deepseek.com
deepseek-chat
```

API-ключ хранится на сервере отдельно от основной конфигурации и не возвращается через API приложения.

## Повторный перевод и редактирование

Главу можно отправить на повторный перевод с дополнительным указанием.

Например:

```text
Сохрани китайские имена.
Не переводи названия техник.
Убери лишнюю литературность.
Не добавляй пояснений.
```

Для такого запроса используется отдельный revise-pipeline.

Также перевод можно изменить вручную непосредственно из интерфейса.

Если текст главы был изменён:

- старые MP3 этой главы удаляются;
- статус TTS сбрасывается;
- глава снова считается готовой к озвучке.

Это предотвращает ситуацию, когда текст и аудиоверсия относятся к разным версиям перевода.

---

## Проверка качества

Для переведённых глав предусмотрена автоматическая проверка подозрительных результатов.

Она позволяет обнаруживать, например:

- слишком короткий перевод;
- аномальное соотношение длины оригинала и перевода;
- возможный обрыв генерации;
- другие признаки неудачного ответа модели.

Проблемную главу после этого можно отправить на повторный перевод отдельно.

---

## Читалка

Встроенный интерфейс позволяет работать одновременно с оригиналом и переводом.

Доступны:

- китайский оригинал;
- русский перевод;
- параллельное отображение оригинала и перевода;
- ручное редактирование перевода;
- переход между главами;
- запуск перевода и TTS непосредственно для выбранной главы.

Diff-режим сопоставляет текст по абзацам.

Это не семантический alignment: если модель изменила структуру абзацев, интерфейс просто показывает соответствующие колонки без попытки автоматически восстановить соответствие предложений.

---

## Озвучка

Для синтеза речи используется:

```text
edge-tts
```

Настраиваются:

- голос;
- скорость;
- громкость.

По умолчанию:

```text
ru-RU-SvetlanaNeural
rate: -4%
volume: +0%
```

Длинный текст автоматически разбивается на части.

Для одной главы могут быть созданы:

```text
001_ru_part001.mp3
001_ru_part002.mp3
001_ru_part003.mp3
...
```

Плеер воспроизводит их последовательно как одну главу.

---

## Очередь задач

Перевод и TTS выполняются через постоянную очередь задач в SQLite.

Задача может находиться в состоянии:

```text
queued
running
done
error
canceled
```

Dispatcher регулярно получает задания из БД и запускает соответствующие worker-потоки.

Значения по умолчанию:

```text
LLM concurrency: 1
TTS concurrency: 2
```

Лимиты настраиваются.

Для локального `koboldcpp` один LLM-поток является рекомендуемой конфигурацией, поскольку одна модель обычно выполняет inference последовательно.

При временной ошибке перевода выполняются повторные попытки. После превышения лимита глава и задача переходят в состояние `error`.

Если сервер был остановлен во время обработки, задачи со статусом `running` возвращаются в очередь после следующего запуска dispatcher.

---

## Отмена и повторный запуск

Из интерфейса можно:

- отменить задачу;
- повторить неудачный перевод;
- заново озвучить главу;
- выполнить revise;
- удалить книгу вместе с её задачами.

Обработка организована по главам, поэтому сбой одной главы не требует повторного запуска всей книги.

## Сохранение позиции

Позиция чтения и прослушивания хранится отдельно для пользователя и книги.

Сохраняются:

```text
chapter_num
position_sec
```

Это позволяет продолжить работу с книгой после повторного входа или с другого устройства.

## Legacy import

Приложение умеет подключать результаты, созданные предыдущей версией pipeline.

Можно зарегистрировать готовую книгу с:

- исходным текстом;
- существующим переводом;
- каталогом MP3.

Такая книга работает в режиме `stream` и не требует повторной обработки старых данных.

При необходимости stream-книгу с подходящим исходником можно позднее преобразовать в обычную структуру глав.

## Repository layer

Метаданные приложения находятся в SQLite, а крупные данные — тексты и MP3 — хранятся в файловой системе.

Доступ к БД вынесен в:

```text
app/repositories/
```

Бизнес-логика работает с repository-слоем вместо прямого SQL-доступа.

Это отделяет способ хранения данных от сервисов приложения и упрощает дальнейшую замену реализации БД.

# Ограничения

### edge-tts не является локальным TTS

`edge-tts` использует облачный сервис Microsoft, поэтому для озвучки требуется интернет.

### Local LLM

Производительность локального перевода зависит от используемой модели и оборудования.

Конфигурация проекта оптимизирована прежде всего для последовательной работы одной локальной модели через `koboldcpp`.

### Форматы книг

Основной входной формат текущей версии:

```text
TXT
```

EPUB, DOCX и HTML автоматически не импортируются.

### Определение глав

Автоматический chapterizer ориентирован на стандартные китайские заголовки вида:

```text
第N章 / 第N节 / 第N回
```

Для нестандартной структуры может потребоваться предварительная подготовка исходника.

# Назначение проекта

TranslatorAudioBook-web-app — специализированный self-hosted инструмент для обработки больших переводных веб-романов.

В отличие от одноразового script pipeline приложение сохраняет состояние каждой главы и позволяет независимо управлять этапами:

```text
исходник
   ↓
перевод
   ↓
проверка / исправление
   ↓
TTS
   ↓
чтение и прослушивание
```

Основной акцент сделан на:

- воспроизводимой обработке больших книг;
- независимом состоянии каждой главы;
- локальном и API-based переводе через единый интерфейс;
- восстановлении после ошибок;
- повторной генерации только необходимых данных;
- многопользовательской работе;
- разделении API, бизнес-логики и слоя хранения.

Проект развивается как полноценное self-hosted приложение, а не как набор связанных CLI-скриптов.

Подробные архитектурные решения и история перехода от предыдущего pipeline находятся в `SPEC.md`.
