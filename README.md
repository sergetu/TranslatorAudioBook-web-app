# TranslatorAudioBook-web-app

**TranslatorAudioBook-web-app** — личный конвейер «китайский веб-роман → перевод → озвучка» в виде веб-приложения: загрузил txt, книга нарезалась на главы, перевелась, озвучилась — и можно читать и слушать.

Всё началось с того, что я хотел читать и слушать один китайский веб-роман. Сначала это был набор CLI-скриптов: исходник резался на куски, переводился локальной моделью, озвучивался через edge-tts — и в конце лежала папка с 751 mp3. Работало, но каждое действие было ручным: перенести файл, запустить скрипт, дождаться, проверить. Захотелось, чтобы это был «нормальный» сервис — со своей библиотекой, очередью, читалкой и плеером, доступный по сети.

Проект сделан для себя и развивается под реальные сценарии нескольких пользователей в локальной сети. Основной приоритет — предсказуемое поведение: главы нарезаются на исходнике, перевод и озвучка идут через единую очередь с ретраями, а удалить или отменить задачу можно в любой момент.

## Возможности

**Библиотека и пользователи**

- email + пароль, первый зарегистрированный пользователь становится админом;
- у каждого пользователя свои книги, владелец видит только своё;
- регистрация включается/выключается настройкой.

**Книги и главы**

- загрузка txt прямо через браузер (utf-8 или gb18030 определяется автоматически);
- автоматическая нарезка на главы по `第N章 / 节 / 回` — глава определяется на исходнике, до перевода;
- у каждой главы свой статус: не переведена → переведена → озвучена;
- перевод, озвучка, ретрай и скачивание — отдельно для каждой главы;
- у книги может быть готовый «легаси»-перевод с аудио без разбивки на главы — такой импорт сохраняется как есть, отдельным режимом.

**Перевод**

- два провайдера за одним интерфейсом:
  - `local` — своя модель через koboldcpp (проверено с HY-MT1.5-7B, формат raw и chat);
  - `deepseek` — DeepSeek API (ключ задаётся в админке);
- системный промпт перевода редактируется в админке;
- пере-перевод главы «с замечанием»: написал, что поправить (имена, стиль, вольности) — глава переводится заново с учётом замечания;
- ручная правка перевода прямо в читалке (после правки аудио старой версии сбрасывается).

**Чтение**

- читалка оригинала и перевода;
- режим диф: оригинал и перевод рядом, по абзацам;
- из главы одной кнопкой: перевести → озвучить → слушать.

**Озвучка и плеер**

- edge-tts (голос настраивается), текст главы режется на части по размеру;
- длинные главы озвучиваются частями, плеер играет их подряд с автопереходом;
- повторная озвучка одной главы, отмена задачи из очереди.

**Скачивание**

- глава: `txt` или склеенный `mp3`; книга: перевод целиком, исходник, `zip` всех аудио.

## Быстрый старт

```bash
# 1) зависимости (Python 3.11+)
pip install -r requirements.txt

# 2) собрать фронт (один раз, нужен Node)
run\06_build_web.cmd        # npm install + vite build -> web\dist

# 3) запустить сервер (API + фронт + диспетчер очереди)
run\05_serve.cmd
#    или: python -m uvicorn app.main:app --host 0.0.0.0 --port 8090
```

Открыть `http://<адрес-машины>:8090` и зарегистрироваться — **первый пользователь становится админом**.

Дальше:

1. в библиотеке загрузить txt книги;
2. нажать «Нарезать на главы»;
3. в админке указать провайдера перевода (своя модель или ключ DeepSeek);
4. запустить перевод недостающих глав и озвучку переведённых;
5. читать в диф-режиме, слушать из плеера.

### Локальный перевод своей моделью

Если перевод идёт локальной моделью — сначала поднять koboldcpp:

```bash
run\01_start_model.cmd      # порт 5003, контекст 8k
```

URL модели, контекст и формат (raw/chat) настраиваются в админке.

## Структура

```text
TranslatorAudioBook-web-app/
├── app/                     # бэкенд FastAPI
│   ├── main.py              # API-роуты + раздача собранного фронта
│   ├── config.py            # пути, настройки; секреты — в data/secrets/
│   ├── db.py                # SQLite (WAL), схема и лёгкие миграции
│   ├── repositories/        # слой данных: контракт (_base.py) + sqlite_repo.py
│   │                        #   сервисы не знают про SQL — задел под другую БД
│   ├── services/            # auth, chapterizer, translator (local/deepseek),
│   │                        #   tts, quality, download, pipeline, legacy_import, books
│   └── workers.py           # диспетчер очереди (LLM — 1 задача, TTS — до 2)
├── web/                     # фронт: Vite + React + Redux Toolkit + SCSS
│   ├── src/                 #   исходники
│   └── dist/                #   готовая сборка (раздаётся сервером)
├── run/                     # cmd-скрипты запуска (модель, сервер, сборка)
├── requirements.txt
└── SPEC.md                  # архитектурная документация
```

`data/` (библиотека книг, аудио, секреты, БД) в git не входит — создаётся автоматически при первом запуске: `data/library/`, `data/uploads/`, а в `data/secrets/` генерируется `jwt_secret`. Ключ DeepSeek туда же пишет админка.

## Ограничения

- **edge-tts — облачный сервис Microsoft.** Озвучка требует интернета, голоса не «локальные».
- **Локальная модель — один слот.** koboldcpp обрабатывает запросы последовательно, поэтому параллельность LLM-задач = 1. На слабой машине перевод главы занимает минуты; DeepSeek — десятки секунд на главу.
- **Главы ≠ абзацы перевода.** Диф-режим выравнивает по абзацам; если их число не совпало — просто две колонки.
- **Первый пользователь — админ, и это навсегда** (в текущей версии).
- Внутренняя документация и детали решений — в `SPEC.md`.

## Статус проекта

TranslatorAudioBook-web-app — небольшой личный проект: инструмент «для себя», который дорос до веб-приложения с пользователями и очередью.

Здесь нет цели «сделать коммерческий сервис»: нет SMS-подтверждений, биллинга и маркетинга. Зато есть то, что важно для реального использования дома: понятный статус каждой главы, честные ограничения вместо тихих падений и возможность пере-перевести или переозвучить одну главу, не перегоняя всю книгу.

Стек проверен на реальном сценарии: книга на 700+ тыс. знаков, 307 глав, часть переведена и озвучена; приложение крутится в локальной сети.
